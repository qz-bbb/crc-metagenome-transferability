# R2 v2.0.0 source-access instructions

The cleaned software and exact ENA snapshots are separated within the tagged repository. `RELEASE_PREPARATION_VALIDATION.md` and its JSON preserve the historical pre-release checkpoint; their local-only status is not the current access status. Publication changes neither scientific rules nor the scope of prior computational checks.

This extension builds on the previously validated M7 generator package. It adds a strictly checked small-source recovery route and separates historical provenance from fresh retrieval. It changes no association, panel, preprocessing, classifier or evaluation rule.

## What is provided

- m7_recovery/recover_m7_sources.py with family-specific, bounded acquisition and explicit local snapshot import.
- m7_recovery/m7_source_inventory.json: exact source URLs, sizes, SHA-256 and attribution boundary.
- m7_recovery/provenance/: two original retrieval receipts and one aggregate historical audit summary; no individual source records.
- SOURCE_RIGHTS_AND_ACCESS.md: what was checked, successful MicrobiomeHD recovery, ENA order-only drift/temporary failure, and licence distinctions.

Example commands from this candidate directory, each using a fresh external destination:

Keep the helper in the shipped `m7_recovery/` directory. Its documented nested layout protects the entire parent package, not just the helper subdirectory.

```text
python -B m7_recovery/recover_m7_sources.py --root ../../recovered_inputs/microbiomehd --family microbiomehd
python -B m7_recovery/recover_m7_sources.py --root ../../recovered_inputs/ena_live --family ena
python -B m7_recovery/recover_m7_sources.py --root ../../recovered_inputs/ena_frozen --family ena --local-dir ../source_snapshots/ena_20261010
```

For the local-import example, extract the full tagged repository archive. If using code-only and ENA-only assets, extract both preserving the sibling `r2_reproducibility/` and `source_snapshots/ena_20261010/` directories. The snapshots remain separate from the code-only package. The helper verifies original byte hashes and creates a fresh `local_verified` import receipt without changing historical sidecars.

The optional second command may reject a live report whose byte order differs, even when its row contents agree. That is intentional: this route reproduces a particular historical source, not the latest project metadata. Use the third command for exact archived inputs. Do not sort a response or edit the expected hash to make it pass.

Use the recovered q/effect paths in the historical generator config. Use recovered ENA files and copied original provenance sidecars in the identity-enrich config. The aggregate identity_audit_summary.json can be copied to the expected 05_review location in a locally generated multicohort tree; keep its pinned SHA, explicitly label it a historical checkpoint, and do not claim to have regenerated the broader source/clinical audit.

## Release and scientific boundaries

The author authorized R2 code and exact ENA snapshot publication on 2026-10-11. The snapshots are preserved in a separately attributed repository directory so the linked versioned archive contains them. MicrobiomeHD tables are not redistributed; only pinned recovery routes are provided. Source-specific rights remain applicable and project MIT does not relicense third-party records. Use actual identifiers from the new release and archive; do not substitute the historical v1.0.1 DOI.

Public access is not a complete fresh-environment/full-model replay, nor author scientific sign-off. The broader aggregate identity checkpoint is not regenerated by this helper. Review the execution-specific reports and remaining limits before making any reproducibility claim.

No journal submission, new fee or model-wide refit is performed by these scripts.
