# CRC R2 reproducibility workflow — v2.0.0

This is the R2 software component of release v2.0.0 for computational replay of completed analyses. It does not assert author scientific review, independent biological validation, or reproduction of the original preregistration chronology. The M7 extension adds three families of historical intermediate generators. Read `M7_GENERATION_GUIDE.md` and `M7_VALIDATION.md` for that extension; `VALIDATION.md` and `validation_summary.json` retain the explicitly labeled prior baseline evidence. The subsequent source-recovery checkpoint is documented separately in `SOURCE_RIGHTS_AND_ACCESS.md` and `RELEASE_PREPARATION_VALIDATION.md`; historical reports retain their dated pre-release status. Current access instructions are in `RELEASE_PREPARATION.md`. Publication adds no new scientific results.

## 1. Environment

Use Python 3.12.10 and `requirements.txt` in a fresh virtual environment for independent reproduction. The prior baseline used an independent venv populated from already-installed local distributions, without system site-packages; its network pip installation failed because of missing proxy SOCKS support. ## 2. Recover official processed sources

`source_inventory.json` pins eleven official ExperimentHub RDA resources dated 2021-03-31, a commit-pinned official cMD metadata RDA, and the two Zenodo 15069069 v1 archives. It records exact URLs, byte counts, SHA-256, and archive MD5 where supplied by Zenodo. It contains no individual sample records.

Keep inputs outside this code directory. The downloader permits only listed official HTTPS hosts and a 20 MB batch ceiling. It never requests raw reads, credentials or costs. Already-present files are reused only after exact hash verification.

```text
python -B source_access.py download --root ../inputs --family cmd
python -B source_access.py reconstruct-cmd --root ../inputs
python -B source_access.py download --root ../inputs --family mp4
python -B source_access.py extract-mp4 --root ../inputs
```

The reconstructed baseline metadata has the historical exact SHA-256. The reconstructed matrix has the same ordered axes and exact parsed float64 values as the frozen 944 × 1,395 historical matrix. Gzip wrappers and decimal serialization can differ; `input_contract.tsv` therefore accepts either the original file SHA-256 or the recorded exact canonical matrix hash. This fallback also applies to the two regenerated historical 1,395 × 301 matrices. It verifies all axes, order and values without a numerical tolerance. Other historical inputs remain strict SHA-256 files.

Before historical-full or identity enrichment, recover the remaining named M7 sources with `m7_recovery/recover_m7_sources.py` as described in `RELEASE_PREPARATION.md`. ENA exact dated snapshots are preserved separately under `../source_snapshots/ena_20261010` in the full repository archive and require explicit hash-verified local import; the moving API was not accepted as an exact replacement. The bundled broad identity summary is a frozen aggregate checkpoint, not regenerated by this helper. Third-party records are not relicensed by the project software `LICENSE`.

Copy `config.example.json` to a local config outside the export. Relative paths resolve against that file, not the working directory. Supply the recovered source tree. Generate the five historical dependencies using `prepare_intermediates.py ... historical-full` before the historical consumer stages, following `M7_GENERATION_GUIDE.md`. `RESULT_SCRIPT_MAP.tsv` distinguishes this extension's actual runs from prior baseline checks and model stages not repeated here.

## 4. Rule ablation and identity sensitivity

Use `config.closure.example.json`. Configure previously generated nested association tables and baseline/multicohort artifacts. After the new identity-enrich stage, set optional `identity_enriched_manifest` to its generated manifest; the identical historical SHA remains required. The broader `identity_audit_summary.json` is a separate frozen audit dependency, not generated by narrow accession enrichment. `closure_input_contract.tsv` is not an acquisition route by itself. Output must be fresh or runner-marked, outside configured sources and the package.

```text
python -B closures.py --config ../config.closure.json rule-init
python -B closures.py --config ../config.closure.json rule-fold --fold 0
python -B closures.py --config ../config.closure.json rule-finalize
python -B closures.py --config ../config.closure.json identity-prepare
python -B closures.py --config ../config.closure.json identity-fit
python -B closures.py --config ../config.closure.json identity-predict
python -B closures.py --config ../config.closure.json identity-evaluate --cohort LiuNN_2022
python -B closures.py --config ../config.closure.json frozen-replay
```

`rule-fold` performs exactly one requested fold; no automatic eleven-fold loop exists. `rule-finalize` requires all eleven completed folds. Original aggregation precision is repaired with exact round-trip reads and retained input hashes. `identity-prepare` selects the audited 1,214 accession-resolved training records; universal participant-level independence is not established by this sensitivity analysis. `frozen-replay` recomputes all eleven selections and 182 point metrics from frozen inputs/predictions without fitting models. Its 20-repeat bootstrap is a behavior smoke check, not the historical 2,000-repeat interval replay.

## 5. Definition-decomposition hook

The `definition_decomposition/` module computes four descriptive effect definitions from fixed MP4 preprocessing and source profiles, without new fitting. Generate its `prior_sparsity` dependency with the new sparsity stage and point the local definition config at those results. Read its `PROTOCOL.md`; run its tests and then `python -B definition_decomposition/run_definitions.py --config ../config.definitions.json`. This M7 extension regenerated all eight sparsity tables and used them to reproduce all nine downstream definition TSVs byte for byte.

## 6. Package boundaries

This code-only archive excludes matrices, individual sample metadata/predictions, models, environments, caches, and all local configurations. The separately attributed ENA reports are included only in the repository's `source_snapshots/` directory and the ENA-only asset. The original working directory contains local inputs and an environment and is unsuitable for recursive sharing. `manifest.tsv` covers this software component; the repository root `PUBLICATION_MANIFEST.tsv` covers the R2 additions.
